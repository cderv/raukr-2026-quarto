## 3. Open scoping questions (answer these to finalize)

These shape what actually gets built. I've marked my recommended default for each so you can
just say "defaults are fine" or correct individual ones.

- **❓Q1 — Deliverable format.** Slides only, slides + hands-on lab (starter/correction
  exercises), or slides + live-coding demos (no formal exercises)?
  *Default: slides + hands-on lab* (mirrors the reference; most infra to reuse).
- **❓Q2 — Topic focus.** What does the Quarto session teach this advanced-R / bioinformatics
  audience? Candidates: reproducible reports/manuscripts (R Markdown → Quarto), presentations
  (revealjs), websites & books, PDF via Typst. Pick one or a few.
  *Default: reproducible reports + a taste of presentations* (best fit for the audience;
  they already know R Markdown, so "what Quarto adds / migration" resonates).
- **❓Q3 — Session length & shape.** One ~2h session? A longer half-day? Multiple linked
  sessions? This drives the number of content blocks and the pacing budget.
  *Default: single ~2h session, 2 blocks.*
- **❓Q4 — Branding / template.** Do you match the **NBIS/RaukR house template** (their site is
  Quarto-based, likely a shared reveal theme/extension) so your deck fits the school, or ship a
  **standalone look** (your own `clean-revealjs` + `_brand.yml`, like the reference)?
  *Default: standalone `_brand.yml` + `clean-revealjs`, but structured so we can drop in the
  NBIS theme later if you have it.* If NBIS provides a template repo/extension, point me at it.
- **❓Q5 — Reviewer panel.** Keep the 3 adapted reviewers (technique, pédagogue, beginner)?
  Add English replacements for the 2 French agents (a copy-editor + a plain-language/tone
  reviewer)? Any new lens (e.g. a "bioinformatics-relevance" reviewer)?
  *Default: technique + pédagogue + beginner + one English copy/tone reviewer (4 total).*
- **❓Q6 — Publishing target.** Standalone GitHub Pages under `cderv/raukr-2026-quarto`,
  Posit Connect Cloud / Quarto Pub, or integrated into the `nbisweden/raukr-2026` site?
  *Default: GitHub Pages (`quarto publish gh-pages`), with a confirm-guarded `just publish`.*
- **❓Q7 — Companion R package?** The reference shipped a `pkg/` (an R package used live). Do
  you want one here (e.g. exercise data / helpers as a package), or keep it package-free?
  *Default: no package* — simpler; drop all `pkg/`-related plumbing.
- **❓Q8 — Sandbox stack.** Confirm the remote sessions need **R + Quarto** (not just Quarto),
  so the session-start hook should install both. Which R version floor? Which Quarto floor
  (reference pinned 1.9.36 but docs recommended ≥1.10.7 pre-release)?
  *Default: install R (via `rig`, latest release) + Quarto latest stable ≥1.9.x in the hook.*
- **❓Q9 — Event metadata.** Exact RaukR 2026 dates, your co-presenter(s) if any, the session
  title, and the room/format (how many participants, 1 instructor?). Needed for `CLAUDE.md`,
  `README`, and the pedagogy reviewer. I'll leave placeholders until you confirm.
- **❓Q10 — Git identity for the sandbox.** Reference used a tracked `.gitconfig` with your
  name/email pulled in by the hook. Reuse the same identity (`Christophe Dervieux
  <christophe.dervieux@gmail.com>`)? *Default: yes.*
- **❓Q11 — License.** Reference used CC BY 4.0 (content) + MIT (code). Same split here?
  *Default: yes.*
