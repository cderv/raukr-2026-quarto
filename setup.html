Setup

What to install before the sessions

You need a working R + Quarto toolchain and an editor. Everything below is standard. If you already render Quarto documents from R, you are ready.

NoteSetup at a glance

Four steps, top to bottom (each links to its details below):

  1. Install R ≥ 4.5, Quarto ≥ 1.9, and an editor.
  2. Get the materials — one line of R, no git or GitHub account needed.
  3. Install the R packages — one install.packages() line.
  4. Check it works — source("00-check-setup.R") from the top folder.

Do steps 2–4 before you arrive: walking in with the toolchain already in place means we start on the content, not the install.

Software

  • R ≥ 4.5.0. The running dataset (penguins) ships in base R only since 4.5 (check with R.version.string). The exercises use the base-R names (bill_len, bill_dep, …), so R ≥ 4.5 is the smoothest path. If you truly can’t upgrade, see the fallback below.
  • Quarto ≥ 1.9. Check with quarto --version and get it from https://quarto.org/docs/get-started/. (1.9 is required: the Typst margin/article layout we use on Day 1 landed in 1.9.)
  • An editor with Quarto support — Positron, VS Code (+ the Quarto extension), or RStudio. All work, and we drive Quarto from the command line too (quarto preview / quarto render), so the editor is your choice.
WarningOn RStudio? The Render button may not use the Quarto you just checked

RStudio can run a different Quarto from the one on your PATH, so quarto --version does not settle what the Render button will use. Day 1’s Typst article layout needs ≥ 1.9.

The quarto R package has a one-line check for exactly this:

# install.packages("quarto")
quarto::quarto_binary_sitrep()

It names the binary each side will use and returns TRUE when they agree. A mismatch looks like:

✔ quarto R package will use '/opt/quarto/bin/quarto'
✖ RStudio IDE render button seems configured to use '/usr/lib/rstudio/bin/quarto/bin/quarto'.

Add debug = TRUE and it also tells you which mechanism configured each one (the PATH, or the RSTUDIO_QUARTO environment variable).

If the two disagree, point RStudio at the install you want with RSTUDIO_QUARTO, or render from the Terminal (quarto render <file>), which we do throughout anyway. If a document looks wrong on Day 1 but renders correctly from the Terminal, this is usually why.

Tip

Typst (the modern PDF path we use on Day 1) ships inside Quarto, so there is nothing extra to install and no LaTeX to set up.

WarningStuck on R < 4.5? (dataset fallback)

The exercises assume base R’s penguins. If you genuinely can’t get to R ≥ 4.5, install palmerpenguins and rename its columns to the base-R names the material uses, so every snippet works unchanged:

# install.packages("palmerpenguins")
library(dplyr)
penguins <- palmerpenguins::penguins |>
  rename(
    bill_len    = bill_length_mm,
    bill_dep    = bill_depth_mm,
    flipper_len = flipper_length_mm,
    body_mass   = body_mass_g
  )

Run this once at the top of a document (or your session) before the exercise code. Upgrading R is still the cleaner path if you can.

Get the materials

The hands-on files live in a small exercises folder (the top raukr-2026-quarto-exercises folder): the starter documents, the reference solutions, and the citation assets (references.bib, apa.csl). The easiest way to get it is use_course() from R. No git, no GitHub account, nothing to unzip by hand, and the same on Windows, macOS, and Linux:

# install.packages("usethis")   # once, if you don't have it
usethis::use_course("cderv/raukr-2026-quarto-exercises")

What it does:

  1. picks a sensible spot (your Desktop by default) and prints where it’s about to download the files. To download them elsewhere, cancel and re-run with a path, e.g. use_course("cderv/raukr-2026-quarto-exercises", destdir = "~/projects").
  2. downloads a ZIP and unpacks it for you into a folder called raukr-2026-quarto-exercises (it prints the exact path). It then asks “Shall we delete the ZIP file?”. Keep it (say No): it’s your one-click reset (see below).
  3. opens the folder — a new RStudio session, or the folder in Positron / VS Code. If it doesn’t pop open, open the folder it printed yourself.
ImportantWhich folder to open — and when

use_course() drops you in the top folder (raukr-2026-quarto-exercises). Do the next two steps (R packages and Check) from there, now, before the session.

When the session starts, open the day folder for that day, not the top folder:

  • Day 1 → open day1-intro/ (double-click day1-intro.Rproj).
  • Day 2 → open day2-projects/ (double-click day2-projects.Rproj).

Each day folder is its own working directory with its own brand and assets, so your renders land right next to your files (there’s no project folder above them to capture the output). One download covers both days. The reference answers are in solutions/day1/ and solutions/day2/ at the top folder. Try the exercise yourself first.

TipReset without losing work (no git needed)

If an attempt goes wrong, get a fresh copy of the day folder (don’t unzip over your working copy):

  • re-run usethis::use_course("cderv/raukr-2026-quarto-exercises"): it makes a new, numbered folder and leaves your old attempt untouched; or
  • unzip the ZIP you kept to a new location.

If use_course() can’t reach GitHub (blocked network / firewall), use the browser: the green Code ▸ Download ZIP button on https://github.com/cderv/raukr-2026-quarto-exercises, then unzip.

R packages

The exercises use nine R packages. The simplest path is a plain install into your R library (it works no matter which day folder you open):

install.packages(c(
  "dplyr", "ggplot2", "gt", "ggokabeito",   # content + a color-blind-safe scale
  "brand.yml", "ggrepel", "prismatic",      # R-side branding for the Typst payoff
  "knitr", "rmarkdown"                      # the engine every .qmd with R code needs
))

Or with pak, which installs the same list in parallel, prefers binaries, and sorts out system dependencies for you:

# install.packages("pak")   # once, if you don't have it
pak::pak(c(
  "dplyr", "ggplot2", "gt", "ggokabeito",
  "brand.yml", "ggrepel", "prismatic",
  "knitr", "rmarkdown"
))
NoteThere’s an renv.lock in the folder (ignore it)

It pins the package versions the course materials are tested against. You don’t need it: the folder ships no .Rprofile and no renv/activate.R, so it is not an activated renv project, and renv::restore() there would install its 65 pinned packages straight into your everyday R library. Use the install.packages() line above.

Check your setup

The exercises folder ships a one-shot check. From the top raukr-2026-quarto-exercises folder, run:

source("00-check-setup.R")

It verifies R ≥ 4.5, Quarto ≥ 1.9, the nine packages, and the base-R penguins data, then renders the Day-1 Typst sample (day1-intro/sample-typst.qmd). That proves the knitr + Typst chain end-to-end and caches the brand’s Google fonts (Albert Sans / Fira Mono), so your first render in the session is instant instead of pausing to download them. Every line should read [ok].

TipPrefer to check by hand?

The one command that proves the toolchain is quarto check. It covers the knitr engine too (the knitr + rmarkdown packages a .qmd with R code needs): it reports your Quarto version and renders a small knitr test document (look for Checking Knitr engine render......OK). If you see rmarkdown: (None), your R packages aren’t installed yet, so do the R packages step and re-run. Then confirm the R side:

R.version.string                          # want >= 4.5.0
"penguins" %in% ls("package:datasets")    # want TRUE on R >= 4.5

And pre-warm the fonts once by rendering the sample yourself: quarto render day1-intro/sample-typst.qmd.
