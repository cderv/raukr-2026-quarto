NoteScope

Turn a set of .qmd into a Quarto project: a navigable, branded website, then make its builds reproducible with freeze and render it to a publishable folder. Two challenges, one project: each is its own hands-on part, with a break between them. Putting the site online is an optional last step (Posit Connect Cloud, free account, no repository), so the folder is what everyone leaves with. Everything runs on base-R datasets::penguins (R ≥ 4.5), so there’s no data to download.

Before you start: work through the Setup page if you haven’t. Its 00-check-setup.R confirms R, Quarto, and the packages this lab uses. The optional branded-plot stretch also uses brand.yml.

Starting point: a shipped set of pages. You don’t start from a blank folder. Open your day2-projects/ folder from the exercises download (double-click day2-projects.Rproj, see the Setup page). It holds two content pages that already render on their own but are not yet a project:

  • index.qmd — a home page;
  • analysis.qmd — a penguins analysis with a figure and a table.

Render one page to confirm it works: quarto render analysis.qmd gives a normal HTML page (analysis.html right next to its source), since the folder isn’t a project yet. Your job across the two challenges is to make it a site, then ship it. Everything you render lands inside day2-projects/. There’s no project folder above it, so nothing redirects your output. A finished reference is in solutions/day2/ if you get stuck or fall behind.

1 Website Challenge

Goal: turn the day2-projects/ pages into a navigable, branded website that renders locally to a _site/ folder.

Note Tasks

  1. In day2-projects/, create a _quarto.yml that declares the project and a website with navigation:

    project:
  type: website
  output-dir: _site
website:
  title: "Penguin Lab"
  navbar:
    left:
      - href: index.qmd
        text: Home
      - href: analysis.qmd
        text: Analysis
format:
  html:
    theme: [cosmo, brand]

    The theme: list is a stack of layers, and later layers win. brand is the layer that reads your _brand.yml (you add that file in step 3), so it has to come after cosmo to override its colors. Until then brand adds nothing and you get plain cosmo.

  2. Render the whole folder: from inside day2-projects/, run quarto render (or quarto preview). Because a _quarto.yml is now present, Quarto treats the folder as one project and builds both pages into _site/.

  3. Brand it. Add a day2-projects/_brand.yml so the site shares one palette:

    color:
  palette:
    teal: "#4C979F"
  primary: teal
typography:
  fonts:
    - family: Albert Sans
      source: google
  base:
    family: Albert Sans

    Re-render. The navbar and links pick up the palette automatically, and the text is set in Albert Sans.

  4. (stretch) Two things make the within-page versus across-page rule concrete. First, on analysis.qmd, drop @tbl-means into a sentence: it resolves to Table 1 because the reference and its table share one page (exactly as yesterday). Second, notice index.qmd already links to the analysis with a plain Markdown link, [analysis](analysis.qmd). That’s deliberate, because across pages there is no auto-numbering (a book feature, not a website one), so a plain link is how you connect website pages.

2 Ship it Challenge

Goal: make the project’s builds reproducible with freeze, then render it to a publishable _site/ folder. (Publishing to Pages is the watch-me demo. You produce the folder.)

NoteStarting point

Keep going with your Website Challenge day2-projects/. If you didn’t finish it, open the ready-made solutions/day2/ project (a complete Part-1 site) and do the steps below in there.

Note Tasks

  1. Add freeze to your project’s _quarto.yml so unchanged pages aren’t re-executed on every build:

    execute:
  freeze: auto      # re-execute a document only when its own source changes

  2. See the skip. Run quarto render once (the code runs; _freeze/ is written). Run quarto render again without editing: the R cell is skipped, its result reused from _freeze/ (the log shows no compute). For a visible tell, drop a cell with cat(format(Sys.time())) on analysis.qmd: on the frozen second render the printed timestamp does not change: a pass/fail you can see, not just an absence in the log. Now change the plot’s code on analysis.qmd and re-render: only that page re-runs (and the timestamp finally ticks).

  3. Find the shipped site under _site/: that folder is what you publish. Point any static host at it (an internal server, your department’s pages, a hosting service).

  4. (optional, if there’s time) Put it online. From your project folder:

    quarto publish posit-connect-cloud

    The first run opens a browser to sign in (a free Posit account is enough, and no repository is needed), then uploads the _site/ you just built. You get a URL you can open on your phone.

  5. (note, not a step) renv::snapshot() writes an renv.lock that pins the packages: the second reproducibility leg, so a teammate (or CI) rebuilds the same environment.

Quarto docs

Freeze · Publishing

Note You should see

On the second render (no edits between them), the log shows the R cell skipped (reused from _freeze/), and the cat(format(Sys.time())) line prints the same time it did on the first render. That frozen timestamp (and the quiet log) is exactly what lets CI render the site with no R at all. Edit a page’s code, and only that page re-runs, its timestamp finally advancing.

TipHint
  • freeze: auto re-executes a document when its source changes (prose or code) and reuses _freeze/ when it hasn’t, so an unchanged page never re-runs. freeze: true goes further: never re-execute on a project build (the CI mode).
  • Frozen results live in _freeze/: commit that folder so CI can render without R.
  • output-dir (default _site) is the whole deliverable: publish the folder, don’t rebuild on the host.
NoteSolution: the freeze block and the render flow

Add to your project’s _quarto.yml:

execute:
  freeze: auto

An optional visible tell: put this on analysis.qmd. A frozen render reuses the old value, so the printed time stays put.

cat(format(Sys.time()))

From inside your project folder (day2-projects/):

quarto render     # 1st build: runs the code, writes _freeze/ and _site/
quarto render     # 2nd build, no edits: the cell is skipped, timestamp unchanged
# then change the plot code on analysis.qmd and render again: only that page re-runs (time ticks)

To publish, point a host at _site/, or upload it with one command:

quarto publish posit-connect-cloud

3 Troubleshooting

Tip If a render misbehaves
  • Rendered, but can’t find the HTML? Before you add _quarto.yml, a single-page render writes the HTML next to its source in day2-projects/. Once _quarto.yml is present, a project render collects both pages under day2-projects/_site/. Look in those two places.
  • YAML is indentation-sensitive. If rendering fails before any code runs, check _quarto.yml for stray spaces, tabs, or unmatched quotes.
  • “No project” / pages don’t link? The _quarto.yml must be inside day2-projects/, and href: paths are relative to the source folder, not _site/.
  • Brand not applied? Two causes. The file must be in day2-projects/ (the project root), and brand must come last in the theme: list: theme: [cosmo, brand] gives you the palette, while theme: cosmo on its own keeps cosmo’s colors and only the fonts change. Re-render after either fix. For plots, the palette needs library(brand.yml) + theme_brand_ggplot2() (the file alone doesn’t reach ggplot).
  • A cross-reference shows ?@…? The cell label must start fig-/tbl-/eq- and be unique, and remember it only resolves within one page on a website.
  • Freeze didn’t skip the cell? It skips only when the source is unchanged since the last build: any edit (prose or code) re-runs that page. Delete _freeze/ to force a clean rebuild.
  • Missing package? install.packages("<name>") (or renv::restore()) and render again.
