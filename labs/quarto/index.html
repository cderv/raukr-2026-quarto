Introduction to Quarto — Lab

RaukR 2026 · Day 1

NoteScope

Build one penguins document with the authoring extras, then cite it and render it as a branded Typst PDF. Two challenges, one document: each is its own hands-on part, with a break between them. This is your manuscript / team-project path, the same route from an analysis to a submittable write-up. Everything runs on base-R datasets::penguins (R ≥ 4.5), so there’s no data to download.

Before you start: work through the Setup page if you haven’t. Its 00-check-setup.R confirms R, Quarto, and the packages this lab uses.

You are working in the day1-intro/ folder from the exercises download (open day1-intro.Rproj). See the Setup page. Everything you render is written next to your files. You start from a file that is already there, authoring-starter.qmd, and the other files are used later, each at the step that names it (the folder’s README lists them).

TipComing from R Markdown? (optional, 2-minute aside)

You do not need to convert anything to work natively in Quarto. Start with .qmd directly. But if you have an .Rmd you want to bring over:

  • it renders as-is (Quarto reads .Rmd too).
  • cell options move from the chunk header to the #| “hash-pipe” (one YAML option per line).
  • knitr::convert_chunk_header("doc.Rmd", output = "doc.qmd") does the mechanical part.

That’s the whole migration. The rest of this lab is native .qmd.

1.1 Cross-reference the figure

Goal. Turn the scatter plot into a numbered figure with a caption, and refer to that number from the prose. Two edits: an option on the cell, and a reference in the body text above it.

Docs: Cross-references.

Note You should see

A caption Figure 1: … under the plot, and the sentence above it opening with a live Figure 1 link.

TipHint

Ask yourself: how does Quarto learn that this cell is a figure worth numbering, and what to call it in the text?

Mechanism: a cell becomes cross-referenceable when its label starts with a known prefix (fig- for a figure) and is unique in the document. The caption is a second cell option. Label, caption and the @fig-something reference work together: a reference with no matching label renders as ?@fig-something.

NoteSolution

On the plot cell:

#| label: fig-bill
#| fig-cap: "Bill length versus depth, colored by species."

And the sentence above the cell, rewritten to point at it:

@fig-bill shows that within a species the bill has a characteristic shape, so the species form
clusters.

1.2 Cross-reference the table

Goal. Same mechanic on the summary table under Mean measurements: a numbered, captioned Table 1, introduced by a sentence that links to it. The gt call is already written.

Docs: Cross-references for tables.

Note You should see

Table 1: … above the table (table captions go above, figure captions below), and a sentence introducing it with a live Table 1 link.

TipHint

Ask yourself: figures and tables are numbered in separate sequences, so which label tells Quarto this one is a table?

Mechanism: #| label: tbl-summary and #| tbl-cap: on the cell, @tbl-summary in the prose. The prefix decides both the sequence and the word (“Figure”, “Table”) Quarto prints.

NoteSolution

On the gt cell:

#| label: tbl-summary
#| tbl-cap: "Mean measurements per species."

And above it:

@tbl-summary reports the mean bill measurements and body mass per species.

1.3 Move the counts into the margin

Goal. Put the species-counts table in the right margin, beside the paragraph that mentions it, instead of in the main text column.

Docs: Article layout.

Note You should see

The counts table in the right-hand margin, level with “The species are not evenly represented:”, and the main text column unchanged in width.

TipHint

Ask yourself: the R does not change, so where do you tell Quarto that this output belongs somewhere else on the page?

Mechanism: #| column: margin on the cell. That option also takes body, body-outset, page and screen. For prose rather than cell output, use a ::: {.column-margin} div.

NoteSolution

On the counts cell:

#| column: margin

1.4 Make the figure accessible

Goal. Make the figure readable by someone who cannot distinguish the colors, and by someone using a screen reader.

The plot separates species by color alone, in ggplot2’s default palette, which is not color-blind-safe. This is the one step that edits the R: two changes to the plot, one option on the cell. ggokabeito is already loaded in the setup cell.

Docs: HTML accessibility · Figure alt text.

Note You should see

Each species drawn with its own shape as well as its own color, in the Okabe-Ito palette (orange, blue, green rather than ggplot2’s salmon, green and blue), and one legend for both color and shape. The alt text is not visible on the page: to check it, view the page source and confirm the <img> tag carries your alt="…". The finished figure looks like this:

TipHint

Ask yourself: someone who cannot separate your three colors needs a second way to tell the species apart. What else can aes() map? And where would a description of the plot go, when everything else about this figure is a cell option?

Mechanism: map shape = species alongside color = species in aes(), and add scale_color_okabe_ito(). The description is the cell option #| fig-alt:. It is not the caption: the alt text stands in for the image, so it describes what the plot shows, not what it is.

NoteSolution

On the plot cell, next to the label and caption:

#| fig-alt: >-
#|   Scatter plot of bill depth against bill length for penguins of three species, each drawn in a
#|   distinct color and shape. The three species form largely separate clusters.

And in the plot itself:

ggplot(penguins, aes(bill_len, bill_dep, color = species, shape = species)) +
  geom_point(alpha = 0.8) +
  scale_color_okabe_ito() +
  labs(x = "Bill length (mm)", y = "Bill depth (mm)", color = "Species", shape = "Species") +
  theme_minimal(base_size = 12)

Naming both color and shape in labs() merges them into a single legend.

Tip Optional accessibility check

Your figure now has alt text and redundant color/shape encoding. To check the whole page:

  • add axe: {output: document} under format: html, re-preview, and a WCAG report appears on the page (drop it again before you publish). See Quarto’s accessibility docs.

1.5 Add a numbered equation (stretch)

Goal. Add the bill-shape ratio (bill length divided by bill depth) as a numbered display equation, and refer to it from the prose.

One caution: inside $$…$$, bill_len can render as a subscript, so escape the underscore as bill\_len.

Docs: Equations.

Note You should see

The formula centered on its own line with (1) at the right margin, and the sentence above it linking to that number.

TipHint

Ask yourself: display math is not a cell, so the label cannot be a cell option. Where else could it attach?

Mechanism: the label is an attribute on the closing $$, written {#eq-ratio}. The eq- prefix makes it a numbered equation, and @eq-ratio links to it like @fig- and @tbl-.

NoteSolution 
A compact descriptor of bill shape is the length-to-depth ratio (@eq-ratio):

$$
\text{ratio} = \frac{\text{bill\_len}}{\text{bill\_dep}}
$$ {#eq-ratio}
Note Checkpoint: the whole document

A numbered Figure 1 (the bill scatter, three separate clusters), a numbered Table 1, and the counts in the right margin. @fig-bill and @tbl-summary render as live links, with no ?@ markers anywhere. If you did the stretch step, you also have a numbered Equation 1.

2 Citations Challenge

Goal: cite the report, then render the same document as a branded Typst PDF.

NoteStarting point

If you finished the Authoring Challenge, keep going in your own my-report.qmd. Otherwise open day1-intro/authoring-checkpoint.qmd (the same report with Part 1 already done), save a copy of it as my-report.qmd in that same day1-intro/ folder (next to references.bib / apa.csl / _brand.yml, which the steps below resolve by name), and continue from there. From here on the instructions say my-report.qmd, whichever route you took.

Note Tasks

  1. Point the document header at the shared bibliography and citation style:

    bibliography: references.bib
csl: apa.csl

  2. Cite the two sources the opening paragraph already credits, without rewriting it. The sentence ending “…collected at Palmer Station, Antarctica.” takes the data citation before the period (Antarctica [@gorman2014].), and the sentence crediting the palmerpenguins package takes [@horst2020] the same way. Don’t paste a second copy of either sentence.

  3. Add a References section where the list should appear:

    ## References {.unnumbered}

::: {#refs}
:::

  4. Give it a real title block so the PDF reads as a paper. Replace your document’s author: line (or add one) with:

    author:
  - name: Your Name
    affiliation: Your Lab, Your University

  5. Render to HTML and confirm both citations resolve, to (Gorman et al., 2014) and (Horst et al., 2020), with a reference list holding both entries.

  6. Switch the output to Typst and render a branded PDF. The branding comes from _brand.yml, which Quarto only picks up when it sits next to your .qmd, so keep my-report.qmd in day1-intro/. You may see unknown font family warnings on the first render. See Troubleshooting if the final PDF still uses a serif font. Two routes:

    • CLI — leave the header as-is and force the target:

      quarto render my-report.qmd --to typst

    • Editor Render button — set format: typst in the YAML header first, then click Render. The button renders whatever format: is declared, so while the header still says format: html the button gives you HTML, not a PDF.

    The PDF is written next to its source in day1-intro/.

Citations · Typst · Brand

Note You should see

In-text (Gorman et al., 2014) and (Horst et al., 2020), a References section formatted in APA with both entries, and, in the Typst PDF, the same citations and reference list, typeset with the RaukR palette. No ?@gorman2014, ?@horst2020 or [?] markers anywhere.

Check the branding applied. An unbranded PDF builds without any error, so check the font instead: a branded PDF is set in Albert Sans, an unbranded one in Typst’s default serif. Serif headings mean _brand.yml isn’t next to your .qmd (see Troubleshooting).

TipHint
  • The @key in [@gorman2014] must match a key in references.bib exactly.
  • csl: sets the style (here APA). Swap the file to restyle every citation at once.
  • Typst reads the .bib itself, so keep bibliography fields plain (avoid LaTeX macros like \emph{} in titles).
  • On the first Typst render, Quarto downloads the brand’s Google fonts. Give it a moment and a network connection.

In the YAML header:

csl: apa.csl

In the prose, append each citation to the sentence that credits its source:

… collected at Palmer Station, Antarctica [@gorman2014]. The data are available through the
**palmerpenguins** package [@horst2020] and are now also included in base R's `datasets` package.

A References section (the list renders inside the #refs div):

3 Bonus — one report per species (optional)

Goal: turn a report into a parameterized one: a single source that renders a separate report per species by passing the species in at render time. This is the “one QC report per sample / one summary per cohort” pattern. Fully optional, so skip it if you’re short on time.

A parameter is a value declared in the YAML that your code can read as params$…. Change the value at render time and the same document produces a different report. No copy-paste.

NoteStarting point

Open day1-intro/parameters-starter.qmd. It contains the report structure, data, and plot. Your task is to make the species an input to the document. A complete reference is available at solutions/day1/penguins-by-species.qmd.

Note Tasks

  1. Declare a parameter with a default in the header:

    params:
  species: Gentoo

  2. Use it to filter in the setup cell. params$species is a value. Keep the existing missing-value checks and add the species condition:

    one <- penguins |> filter(species == params$species, !is.na(bill_len), !is.na(bill_dep))

  3. Use the parameter in the report. Three places, marked TODO 3a, 3b and 3c in the file. Replace the placeholder species in the opening sentence with inline code (`{r} params$species`), and name the species in the closing sentence the same way. Make the caption and alt text track the parameter with !expr. Cell options are YAML, so the !expr tag tells Quarto to evaluate the R expression:

    #| fig-cap: !expr paste0("Bill length versus depth for ", params$species, " penguins.")
#| fig-alt: !expr paste0("Scatter plot of bill depth against bill length for ", params$species, " penguins.")

  4. Render a different species from the CLI with -P name:value. Run this from inside day1-intro/:

    quarto render parameters-starter.qmd -P species:Adelie

    With no -P, the default (Gentoo) is used.

Parameters

TipStretch: dynamic headings and standalone files

Replace the static ## Species at a glance heading with a cell that emits Markdown:

```{r}
#| echo: false
#| output: asis
cat("##", params$species, "at a glance\n")
```

To keep two named reports, render each as a self-contained HTML file:

quarto render parameters-starter.qmd -P species:Adelie    --output adelie.html    --embed-resources
quarto render parameters-starter.qmd -P species:Chinstrap --output chinstrap.html --embed-resources

--output prevents the second render from overwriting the first. --embed-resources puts each plot inside its HTML file, so the reports do not share a figure-support folder.

Note You should see

Rendering with -P species:Adelie gives a report whose sentences, figure caption, alt text, point count, and plot are all about Adelie. Nothing says Gentoo. Rendering without -P produces the Gentoo report. If you completed the stretch task, the heading also names the selected species.

TipHint
  • Parameters must have defaults: params$species has to resolve when no -P is passed.
  • -P takes name:value (-P species:Adelie). Pass several with repeated -P flags.
  • The plot must use the filtered object one, not the full penguins data.

The complete, runnable solution is solutions/day1/penguins-by-species.qmd. Open it to compare your work or render it with different -P species: values. You can also take the source:

4 Troubleshooting

Tip If rendering fails or the output looks wrong
  • YAML is indentation-sensitive. If rendering fails before any code runs, check the YAML header for stray spaces, tabs, or unmatched quotes.
  • Missing package? install.packages("<name>") (or renv::restore()) and render again.
  • A figure doesn’t appear? Check the path is relative to the .qmd and the filename matches exactly (case included).
  • A cross-reference shows ?@…? The cell label must start with fig-/tbl-/eq- and be unique, and the @ref must match it.
  • A citation shows ?@gorman2014 or [?]? The @key doesn’t match a key in references.bib, or bibliography: isn’t set.
  • references.bib not found, although the download has it? Your .qmd is probably not in day1-intro/ (saved to the top folder, for example). Move it next to references.bib / apa.csl / _brand.yml and render again.
  • Do I need to install Typst? No. Typst is bundled in Quarto ≥ 1.9, so there’s nothing extra to install (no LaTeX either). Check quarto --version.
  • Typst PDF looks unbranded / wrong fonts? An unbranded render succeeds silently, so check the font, not the log: branded is Albert Sans, unbranded is Typst’s default serif. Confirm _brand.yml is in your day1-intro/ folder (next to the .qmd) and you have network on the first render (Quarto fetches the Google fonts once). Missing the file? Download _brand.yml into the folder holding your .qmd.
  • Typst prints unknown font family warnings? Harmless: a gt table names a generic sans-serif in its font stack, and Typst doesn’t recognize that as a family. The PDF still builds, branding included.
  • Prefer to stay in HTML first? Render HTML, get it right, then switch to format: typst. The content is the same.
