Part 1 — Basics

Author a document, land it as HTML.

What you can now build

You know the literate-programming idea. In 2026, one .qmd is your source for:

  • a report (HTML, PDF, Word) — figures, tables, cross-refs, citations;
  • a presentation (these slides are a .qmd);
  • a website or book (Day 2) — many pages, one config;
  • a branded PDF via Typst (a modern PDF engine bundled in Quarto, no LaTeX) — a publication-ready article.

One tool, many outputs, multiple languages: all from one plain-text .qmd you write directly.

  • Frame (not a line): reframe from “Quarto = R Markdown++, nothing new to learn” to “here’s what you can now build” — this audience wants to go further, not be reassured.

How it all works

quarto render report.qmd runs your code, then hands Markdown to Pandoc:

  • Frame: for R, the knitr engine runs your chunks — the same engine as R Markdown. Your .Rmd still renders as-is; knitr::convert_chunk_header() moves it to .qmd cell options when you’re ready.

Anatomy of a .qmd

Three parts: a YAML header, Markdown prose, and executable code cells.

---
title: "A penguin story"
format: html
---

We measured **`{r} nrow(penguins)`** penguins.

```{r}
#| label: fig-bill
#| fig-cap: "Bill length versus depth"
ggplot(penguins, aes(bill_len, bill_dep, color = species)) +
  geom_point()
```

Cell options use the #| “hash-pipe”: one option per line, YAML-valued. Native from the start.

Markdown & content — think in deltas

Follow along

In day1-intro/, create my-report.qmd with format: html. It is the file the lab starts from. Put this cell at the top: everything we write next assumes it. Fallen behind at any point? Open starter.qmd in the same folder and keep going from there.

```{r}
#| label: setup
#| message: false
library(dplyr)
library(ggplot2)
library(gt)
data(penguins)
penguins <- penguins |> filter(!is.na(bill_len), !is.na(bill_dep))
```

You already know Markdown. Quarto adds the research-writing pieces: figures and tables with captions, cross-references (@fig-bill, @tbl-summary, @eq-ratio), math, inline code that reports numbers from the data, and callouts.

  • Say: “From here we build one document together. Render as we go.”
  • Do: make sure the setup cell is in the document, not run in the console. knitr renders in a fresh R process, so a console run never reaches the render and the first figure cell errors.
  • Say (name the file out loud): “my-report.qmd, in day1-intro/” — it is the exact file the Authoring Challenge asks for, so what they build now carries straight into the lab.
  • Frame: the list is deltas over the Markdown they already know — not a Markdown lesson.
  • Timing: this + the next four slides (Figures / Tables & math / Callouts / Inline code) are the live build, ~8–10 min total. One point per slide; don’t polish plots.

Figures & cross-references

A labeled code cell becomes a numbered, referenceable figure:

```{r}
#| label: fig-bill
#| fig-cap: "Bill length versus depth, by species."
#| fig-alt: >-
#|   Scatter plot of bill depth against bill length
#|   for three penguin species, forming clusters.
#| output-location: column
ggplot(penguins, aes(bill_len, bill_dep,
                     color = species)) +
  geom_point(alpha = 0.8) +
  labs(x = "Bill length (mm)",
       y = "Bill depth (mm)")
```

Refer to it in prose with @fig-bill → renders as “Figure 1”, a live link. Labels must start with fig- / tbl- / eq- to be cross-referenceable.

#| fig-alt is the figure’s alt text (the description screen readers announce). Add it to every figure. (#| output-location: column is slide-only: a revealjs placement, not article layout.)

  • Do: add #| label: fig-bill + #| fig-cap to the plot cell, render, show the auto-number appear.
  • Say: “A labeled cell becomes a numbered figure; @fig-bill in prose is a live link.”
  • Say (trap): the label must start fig-/tbl-/eq-, or the ref renders a stray ?@.
  • Do: point at output-location: column — a revealjs cell option that puts the plot in a column beside the code on this slide. (Presentation output-placement — not the article margin layout on the Layouts slide, which doesn’t apply to revealjs.)

Tables

gt (or knitr::kable) turns a data frame into a table; a #| label: tbl- makes it referenceable.

```{r}
#| label: tbl-summary
#| tbl-cap: "Mean bill length per species."
penguins |>
  summarise(bill = mean(bill_len), .by = species) |>
  gt() |> fmt_number(bill, decimals = 1)
```

Then refer to it in prose with @tbl-summary (same mechanic as figures).

  • Do: show the gt cell with #| label: tbl-summary, render, point at the auto-number.
  • Say: “Same mechanic as figures — a tbl- label makes it referenceable; gt or knitr::kable, your call.”
  • Timing: the table is the must-keep; the Math slide is the trim point if Part 1 is tight.

Math

Display math with a label is cross-referenceable too:

$$
\text{ratio} = \frac{\text{bill\_len}}{\text{bill\_dep}}
$$ {#eq-ratio}

renders as Equation 1 below:

\[ \text{ratio} = \frac{\text{bill\_len}}{\text{bill\_dep}} \tag{1}\]

  • Do: show the display-math block with {#eq-ratio}, then the rendered, numbered equation.
  • Say: “Same mechanic again — an eq- label makes the equation referenceable.”
  • Say (trap): inside bare $$…$$ an underscore can trigger a subscript (or an error) depending on the math renderer — escape it as bill\_len (the lab warns about this too).

Callouts

Callouts are first-class Markdown (no package):

::: {.callout-tip}
Base-R `penguins` (R ≥ 4.5) needs no install.
:::

Tip

Base-R penguins (R ≥ 4.5) needs no install.

  • Do: render one callout live — no package, pure Markdown.
  • Say: “Five types — note, tip, warning, caution, important — same syntax, different color.”
  • Frame: next slide closes the live build — inline code.

Inline code

Inline code drops a computed value straight into prose. Put it in a sentence:

We measured `{r} nrow(penguins)` penguins.

It renders with the live count: “We measured 342 penguins.”

The number updates when the data does. Reproducible by construction.

  • Do: show inline code reporting nrow(penguins) from the data — “the number updates when the data does. Reproducible by construction.”

Layouts: body, margin, and beyond

Eyes up — not a live Follow along

The live build is done. The next seven slides are concept, no need to type along. Your document is ready for the Challenge.

The article-layout model puts content in the body, the margin, or a zone wider than the body (in the paged formats: HTML, LaTeX, Typst):

  • page-layout: article / full — the overall grid;
  • margin content — figures, tables, captions, .aside, footnotes;
  • outset / inset — a figure or table that spills beyond the body (outset) or widens toward the page while keeping a margin from the edge (inset);
  • multi-column ::: {.columns} and panels — tabsets + layout-ncol.
  • Do: gloss outset/inset on first use; the rendered visual examples live behind the Learn more links on the next slide, for anyone who wants the full column vocabulary.

Put output in the margin

A cell’s #| column: margin drops its output (figure or table, caption and all) into the margin:

```{r}
#| label: counts
#| column: margin
penguins |> count(species, name = "n") |> knitr::kable()
```

In the lab you’ll use margin layout, the one that does the most for an article. The rest are in the Quarto docs below.

Learn more: Article Layout · Margin content

Make it accessible

Accessibility is a few habits layered on what you already write:

  • Alt text — you already add #| fig-alt: to every figure; it’s what a screen reader announces.
  • Color-blind-safe colors — the default palette isn’t. Reach for Okabe-Ito (scale_color_okabe_ito()) or viridis, and encode by shape/label too, not color alone.
  • Check contrast — WCAG wants 4.5:1 on text. Quarto’s built-in axe runs axe-core on the rendered page: axe: true logs to dev-tools, axe: {output: document} writes the report onto the page itself.

Learn more: HTML Accessibility

  • Hook: your reader might be on a projector in a bright room, have red-green color-vision deficiency (~8% of men), or use a screen reader — the same few habits cover all three.
  • Tie to their plot: the penguins scatter defaults to non-safe colors; one line, scale_color_okabe_ito(), fixes it (the worked report already uses it) — show before/after if time.
  • axe: it’s axe-core (the industry-standard checker), built into Quarto since 1.8 for html/revealjs/dashboard; it runs in the browser on preview and logs to dev-tools — a check-as-you-go tool, not a render/publish gate. Quarto 1.10 polishes the on-page report.

One source → many formats

One key in the header picks the output. The content stays put:

format: [html, typst]     # render several at once
toc: true                 # shared — applies to both
format:                   # …or set options per format
  html:
    toc: false
  typst:
    toc: true
  • Shared vs. per-format — top-level keys (toc, number-sections, …) apply to every format; the format: map overrides them per output.
  • Conditional content — show or hide per format with ::: {.content-visible when-format="html"}.
  • The layout idioms adapt per format: write once, target many.

Learn more: Multiple formats · Conditional content

Execution: set once, override per cell

R Markdown’s knitr::opts_chunk$set() moves into the header. Set defaults once, override per cell:

Header — defaults for every cell:

execute:
  echo: false
  warning: false

A cell — overrides locally with #|:

```{r}
#| echo: true
summary(penguins$body_mass)
```

The header sets the defaults; a cell’s #| wins.

freeze commits computed results to _freeze/ so a project re-render (or CI without R) skips unchanged documents. That’s the Day 2 story.

Learn more: Execution options · Cell options

  • Do (live): add execute: / echo: false to the header, re-render — every code block disappears at once. Then drop #| echo: true on one cell — just that one returns. The delta, made visible.
  • Say: “Same idea as opts_chunk$set(), now declarative YAML — dashes not dots, false not FALSE.”
  • freeze is a one-line teaser only; the real freeze-vs-cache teach is Day 2.

Running & editing

Drive Quarto from the CLI, in whatever editor you like:

quarto preview report.qmd   # live-reloading preview
quarto render  report.qmd   # one-off render
  • RStudio, Positron, and VS Code all work. The visual editor (WYSIWYM — what you see is what you mean) is built into the RStudio IDE, and comes to Positron and VS Code through the Quarto extension.
  • The same quarto render also takes -P name:value: override a document parameter to get one report per sample or species from a single source. (Optional bonus in today’s lab.)
  • Do: run quarto preview report.qmd live — save an edit, show the browser reload; then quarto render for the one-off.
  • Say: “Drive it from the CLI, in whatever editor you like — RStudio, Positron, VS Code.”
  • Params (MENTION, cut-first): mention -P here, where quarto render is on screen — the optional lab bonus does it hands-on (one report per species). Don’t dwell; it isn’t a taught beat.
  • Timing: keep it brief — the room knows cells and Jenny Bryan covers the IDE. Part 1 lands inside its ~18–20 min budget.

From report to article

You have a clean HTML document. The lab ships a Part-2 starter if you need one. To make it a publication-ready article, two more things:

  1. citations — a .bib file and a citation style;
  2. a typeset PDF — via Typst, bundled in Quarto.

This is exactly the path from your analysis to a submission, and to your team-project write-up.

Citations

Follow along

Back in your editor: we add citations to your Part-1 document, or to day1-intro/starter.qmd if you need one.

Point the header at a .bib, then cite with @key:

bibliography: references.bib
csl: apa.csl
The data come from Palmer Station
[@gorman2014].

renders as: … Palmer Station (Gorman et al., 2014).

references.bib already ships in day1-intro/ (excerpt):

@article{gorman2014,
  author  = {Gorman, K. B. and ...},
  title   = {Ecological Sexual ...},
  journal = {PLoS ONE},
  year    = {2014}
}

The reference list renders at the end automatically, or wherever you drop this div:

::: {#refs}
:::

CSL = Citation Style Language. Swap the csl: file to restyle every citation.

  • Do: point the header at references.bib + a csl:, drop [@gorman2014] into a sentence, re-render — the in-text cite resolves and a reference list appears at the end.
  • Say: “One .bib key in your prose becomes a formatted citation and an auto-built reference list — swap the csl: file and the whole style changes.”
  • Gloss CSL if asked: Citation Style Language — the file that decides how citations and the reference list are formatted (APA, Vancouver, a journal’s own style).
  • Helpers: the .bib path is relative to the document — the follow-along file must sit in day1-intro/ next to references.bib/apa.csl. A [?] in the text means a wrong @key, or bibliography: not set in the header.

    orcid: 0000-0003-4474-2498
abstract: |
  Using base-R `penguins`, we show bill shape separates species...

Renders in HTML, PDF, and Typst. Write it once.

Typst — modern PDF, no LaTeX

Typst is a modern typesetting system that ships inside Quarto: nothing to install, no LaTeX toolchain.

format: typst

That is the whole switch. Then re-render:

quarto render report.qmd --to typst

Pre-flight

Typst is bundled from Quarto 1.4+; we require ≥ 1.9 (margin/article layout). Check once with quarto --version.

  • Say: “Typst is deterministic and bundled — nothing to install. LaTeX is still there if you need it, but Typst is what we use in 2026.”
  • Gloss “Typst” on first use.
  • If someone says their PDF is serif despite _brand.yml (only if asked): check for unknown font family: albert sans in the log. That is a font download failure (no network on the first render), not a missing brand file. Colors and layout are still branded.

Branding the PDF — _brand.yml

One _brand.yml carries your palette + fonts to the Typst PDF you just built, and to the plots and tables inside it:

_brand.yml
color:
  palette:
    teal: "#4C979F"
  primary: teal
typography:
  fonts:
    - family: Albert Sans
      source: google
  base:
    family: Albert Sans
  • Same file themes HTML and Typst.
  • The R side (theme_brand_ggplot2() / theme_brand_gt() from the brand.yml package) themes your plots and tables from the same palette.
  • Quarto fetches Google fonts for Typst automatically.
  • Do: add _brand.yml (palette + fonts) and re-render the Typst PDF — colors and type change from that one file. This is the payoff.
  • Say: “One file themes the PDF — and theme_brand_ggplot2() / _gt() pull the same palette into your plots and tables. Tomorrow the same file will brand a whole project.”
  • Helpers: a plot won’t inherit the palette until you add a theme_brand_* helper; the first Typst render fetches the Google fonts, so it needs network once.
