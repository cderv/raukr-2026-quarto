Part 1: Build and structure a project

From one file to a whole site.

Why a project?

Follow along

Open your editor: from here we build one project together.

One .qmd renders alone. A project is a folder Quarto treats as one unit (shared config, one build, one output folder):

_quarto.yml
# at the project root
project:
  type: website
  output-dir: _site # everything renders here
format:
  html:
    toc: true       # set once, every page gets it
  • quarto render builds the whole folder, not one file.
  • Header options set once apply to every page.
  • output-dir: the folder where the built site is written (_site by default). Publish that.
  • Say: “Many files, one project. Open your editor.”
  • Do: add a minimal _quarto.yml; render the whole folder.
  • Say: “This is how the pages of your team project connect.”

Quarto uses the nearest _quarto.yml up the tree as the project root: you add one to day2-projects/, and nothing sits above it, so that folder is your project.

Directory metadata: _metadata.yml

Yesterday a header set the defaults and a cell overrode them. _metadata.yml is that same idea, one scope wider: options for every page in a folder, so you don’t repeat them in each header:

analysis/_metadata.yml
# applies to every .qmd in analysis/
execute:
  echo: false
  warning: false
format:
  html:
    code-fold: true

Same narrow-wins rule, now across files: document header > _metadata.yml > _quarto.yml. Set defaults wide, override narrow.

Websites: pages and navigation

You already set type: website, which makes the folder a site: its pages share one navbar and sidebar. You describe that navigation once, and Quarto builds it:

_quarto.yml
website:
  title: "Penguin Lab"
  # top bar — one entry per page
  navbar:
    left:
      - href: index.qmd
        text: Home
      - href: analysis.qmd
        text: Analysis
  # side menu, built from the files
  sidebar:
    contents: auto

contents: auto even builds the sidebar from the folder, so you don’t hand-list pages.

Listings turn a folder of pages into an auto-generated index (a blog, a gallery of reports) via listing: on a page. One slide’s worth, more in the linked resources.

Project-wide numbering is a book

One brand → the whole project: _brand.yml

Yesterday, _brand.yml branded one Typst PDF. Drop that same file at the project root and Quarto auto-discovers it (no header line, no per-page config):

_brand.yml
color:
  palette:
    teal: "#4C979F"
  primary: teal
typography:
  fonts:
    - family: Albert Sans
      source: google
  base:
    family: Albert Sans
  • Every page and every deck inherits it from that one root file, so you never name it in a page.
  • Add a page later? Branded on render, nothing to wire up.
  • Need an exception? brand: false opts a page out. brand: other.yml points it elsewhere.

Freeze: skip unchanged computations

Follow along

Back in your project’s _quarto.yml.

freeze was one line in Day 1. Compute can be slow: you don’t want every prose edit to re-run a 20-minute model fit. Two tools, easily confused:

  • cache: the compute engine’s cache, not Quarto’s. It defers to knitr (R) or Jupyter Cache. Per-cell, kept until that cell’s code changes, and it works in a single document.
  • freeze: Quarto’s switch for when a document re-executes. Project-only: rendering one file always runs it. Results live in _freeze/, refreshed only when its source changes. Commit it and CI (the automated build) rebuilds with no R at all.
# _quarto.yml
execute:
  freeze: auto        # re-execute a document only when its source changes

freeze: auto is the setting to adopt. freeze: true hands you full control instead.

  • Say: “A prose edit should not rerun a 20-minute model.”
  • Contrast: cache = engine, per cell; freeze = Quarto, per document, project only.
  • Do: add freeze: auto; change one page and render.
  • Payoff: commit _freeze/; CI can build without R.
  • Next: freeze: true gives manual control.

The freeze: true workflow

With freeze: true, a project build reuses _freeze/ even when the source changed. You refresh a page when you choose to, by rendering that one file (a single-file render always executes):

_quarto.yml
execute:
  freeze: true
quarto render analysis.qmd     # runs the code, rewrites _freeze/ — commit it with your change

The loop: edit a page → render that one file → commit _freeze/. Once every page has been frozen once, the project build and CI stay R-free. That’s exactly how quarto.org itself is built.

freeze: auto instead lets the build recompute a page whose source changed. Convenient, but true keeps the trigger in your hands.

  • Say: “With true, only a direct document render recomputes the page.”
  • Precision — don’t say “never runs R”. A page with no _freeze/ entry still executes, and so does a brand-new page added to the project (checked on Quarto 1.10). What true buys is that an edited page is not recomputed by the build. “R-free” is the steady state, once every page has been frozen once.
  • Do: edit analysis.qmd; render that file; show _freeze/ change. Then render the project.
  • Contrast: auto recomputes changed pages; true requires manual refresh.
  • Example: quarto.org uses true and commits _freeze/.

Reproducibility has two parts

freeze pins the results. It doesn’t pin what produced them (the package versions):

  • freeze → _freeze/: do not repeat slow computation.
  • renv.lock → “pin the packages, so the team rebuilds the same environment.”
renv::init()       # once, to start tracking
renv::snapshot()   # write renv.lock
renv::restore()    # rebuild the same env

Together: a colleague (or CI) rebuilds the same site, with or without re-running the analysis.

Learn more: renv

  • Say: “freeze pins results; renv.lock pins package versions.”
  • Timing: drop this first if short.

Publishing

The hands-on part is small: render, then point a host at output-dir.

quarto render              # builds the whole project into _site/
  • _site/ is the whole deliverable. Point any static host at it (an internal server, your department’s pages, a hosting service).
  • Posit Connect Cloud takes it in one command, with a free account and no repository:
quarto publish posit-connect-cloud

The first run opens a browser to sign in, then uploads the folder you just built.
